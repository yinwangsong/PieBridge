当前 epoch 内的冻结特征预取与窗口调度

基线与范围
比较基线为无特征缓存的 FIFO，沿用同一前台推理负载与窗口准入规则。
每种条件从同一初始状态执行完整 12 轮在线训练。只允许本轮内提前计算；
特征用完释放，下一轮重新计算。冻结 proxy、策略模型和离线训练均保持原样。

设计
将一个逻辑训练 batch 的执行分成两部分：冻结 proxy 的特征计算，以及
依赖当前分类头参数的 loss、跳过判断和参数更新。前者可以提前执行；后者
必须等到该 batch 在原训练顺序中轮到，并使用当时最新的分类头与 EMA。
每轮采样得到 batch、样本索引与 proxy 后，才生成该轮的预取候选。

维护最多 32 个逻辑 batch 的特征缓冲区，向前查看最多 128 个 batch。
缓冲区在每轮开始时重新创建，记录对应的 batch ID、proxy 和样本索引。
优先更新已经准备好特征
的队首 batch；否则在剩余 GPU 窗口中选择可容纳的特征计算任务。
为缺少特征的队首预留容量，避免后续特征占满缓冲区后无法推进训练。

同一 proxy 的 1、2 或 4 个原 batch 可合并做一次冻结前向计算，再按原
batch 切分输出。分类头仍以原来的 batch=4 计算 loss 和更新。这是预取实现
中的前向合并优化，其收益包含计算吞吐改善，不能全部归因于异步重叠。
所有前向和更新时间、第一次填充以及最后清空，都计入训练时间。

预期收益与边界
提前计算本身不减少每张图片的前向计算量。收益可能来自两处：将冻结前向
和分类头更新拆开，让更短的操作利用原先放不下完整 batch 的空隙；把相同
proxy 的图片合并前向，提高 GPU 吞吐。前向合并也可以在没有前台推理时使用。
若只提前计算而没有可利用的空隙或合并收益，缓冲与调度开销可能使训练变慢。
因此这里的预取是“分阶段执行 + 有界缓冲 + 同 proxy 合并”，不能将完整收益
解释为缓存命中减少重复计算，也不能事先保证超过 20%。

四种条件
1. FIFO，无缓存：原先的完整 batch FIFO 调度。
2. Reorder，无缓存：原先的完整 batch 窗口重排。
3. FIFO，有预取缓冲：特征按原顺序生产，仅合并相邻且 proxy 相同的 batch。
4. Reorder，有预取缓冲：特征可以跨 proxy 重排，分类头更新保持原顺序。

有效性与核验
每张训练图片在每轮恰好通过其分配的 proxy 一次；每个特征恰好使用一次。
保存生产和消费时间戳，核验特征先产生后使用、样本与 proxy 匹配、轮末缓存清空。
推理请求按墙钟时间释放，不丢请求，报告 p99 响应与截止期超时率。
每轮 evaluation 重新前向计算全部验证图片，四组采用相同的原 batch-4 FIFO。

数值检查
发布的 JIT 卷积内部保留 TF32 许可标志；所有条件使用同一份发布模型。
原 batch 重复计算也存在轻微数值抖动，因此不声称逐位一致。
记录严格逐元素检查结果、归一化特征误差和原逻辑 batch 的 loss 差异，并在
短跑中核对更新决策。最终仍需报告完整训练的准确率、更新次数和路由变化。

统计口径
分别给出 12 轮累计训练时间、12 次全量验证时间，以及包含前台请求清空的总时间。
时间缩短率 = 1 - 新方法时间 / 无缓存 FIFO 时间。
首轮预取和后续填充不放到计时区间之外；不挑选有利 epoch 或固定训练片段。
当前首组条件为既有的 105 ms 周期，每种方法一次；单次测量不报告置信区间。
